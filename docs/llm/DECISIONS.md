# 心智项目关键决策记录

这里记录已经确认、会长期影响开发的产品和架构决策。后续如果需要改变某项决策，应新增一条“替代”记录并说明原因，不直接抹掉历史。

## D-001：采用 API 优先的模块化单体

- 状态：生效中
- 决策：前端页面与后端 API 放在同一个 Next.js 项目和部署单元中，但前端只能通过 API 访问业务数据。
- 原因：当前规模下维护和部署成本最低，同时保留未来拆分后端、增加 App 或海外站的能力。
- 影响：复杂业务规则进入 `src/modules`，API 路由保持轻薄，组件不能直接访问数据库。

## D-002：门户公开，剧本详情采用白名单

- 状态：生效中
- 决策：门户首页和剧本库卡片公开；导演阐述和试读仅白名单会员可看。
- 原因：兼顾公开获客和核心内容保护。
- 影响：游客 API 只返回卡片所需信息，详情接口必须在服务端检查会话。

## D-003：一人一码注册

- 状态：生效中
- 决策：普通用户只能用管理员生成的一次性注册码注册，一个注册码只能成功使用一次。
- 原因：早期控制用户质量和内容访问范围。
- 影响：完整注册码不写入数据库，只保存带密钥的摘要；使用、撤销必须留状态。

## D-004：系统不自动解析上传剧本

- 状态：生效中
- 决策：管理员上传 Word、TXT 或 Markdown 原文件，同时手工填写公开资料和试读内容；系统暂不使用 AI 或格式解析器生成展示内容。
- 原因：不同剧本格式差异大，自动解析失败会增加后台返工和内容错误。
- 影响：原文件只用于购买后交付，前台展示完全来自管理员填写的数据。

## D-005：一个剧本只成交一次

- 状态：生效中
- 决策：每个剧本只能产生一个已完成购买订单。
- 原因：当前售卖的是独家授权，不是重复销售的数字商品。
- 影响：购买必须锁定剧本并使用数据库事务；成交后其他用户不能查看详情或再次购买，但剧本库首页保留不可点击的已售出卡片。

## D-006：完整文件只能由买家下载

- 状态：生效中
- 决策：完整剧本、中英对照或中文制作稿、导演阐述作为私有文件保存。
- 原因：试读与交付文件的权限不同，不能依赖前端隐藏按钮保护内容。
- 影响：文件不进入 `public`，下载 API 必须核验已完成订单和当前用户身份，响应禁止缓存。

## D-007：心源定价与充值优惠分离

- 状态：生效中
- 决策：固定 `1 元 = 100 心源`；剧本统一按心源扣费，不设置账号折扣；优惠通过充值赠送心源实现，最高等效四折。
- 原因：让剧本价格、用户余额和财务流水保持简单、可审计。
- 影响：充值档位允许不同赠送比例，但账号本身没有折扣字段。

## D-008：支付宝暂时只留接口

- 状态：生效中
- 决策：保留电脑网站支付宝支付的适配器边界和数据库结构，但当前不接入真实支付。
- 原因：先完成内容、会员和独家交易闭环，再决定支付上线时间。
- 影响：`PAYMENT_DRIVER` 必须保持 `disabled`；个人中心显示“暂未开放”。

## D-009：初期使用本地私有存储

- 状态：生效中
- 决策：初期剧本文件使用服务器持久磁盘，不使用 OSS。
- 原因：文件体量和业务量较小，本地存储更轻量。
- 影响：所有文件通过 `StorageProvider` 访问；生产必须挂载持久卷并执行异机备份；未来迁移 OSS 时增加适配器并按 SHA-256 校验迁移。

## D-010：保持心智现有视觉语言

- 状态：生效中
- 决策：门户和剧本库保持深色、克制、影视编辑感；门户强调 PV 和作品，剧本库强调专业阅读与独家授权。
- 原因：符合 AI 漫剧公司的品牌定位，并避免后台模板感。
- 影响：新增页面应复用当前排版、颜色、留白和交互节奏，不引入无关主题系统。

## D-011：采用单机 Docker Compose 作为首发部署

- 状态：生效中
- 决策：首发使用反向代理、单个应用容器、PostgreSQL 和两个持久卷。
- 原因：当前阶段不需要 Kubernetes 或微服务平台，单机结构更易维护和恢复。
- 影响：应用和数据库不直接暴露公网；上线前运行迁移、自检和备份；需要 HTTPS、持久磁盘和异机备份。

## D-012：注册协议同意必须由前后端共同校验并留痕

- 状态：生效中
- 决策：白名单注册必须同时同意用户协议和隐私政策；后端拒绝未同意请求，并在用户记录中保存协议版本与同意时间。
- 原因：前端勾选框只能表达交互，不能作为可靠的注册规则或历史凭证。
- 影响：协议升级时更新 `identity/policies.ts` 中的版本；上线前必须补全真实运营主体、联系方式并进行正式合规审阅，不能把当前通用文本视为法律定稿。

## D-013：完整交付包由受保护下载接口动态生成

- 状态：生效中
- 决策：用户购买成功后，原购买按钮直接变为“下载全部交付物料”；服务端核验买家或管理员身份后，从私有存储读取交付文件并生成 ZIP。
- 原因：用户需要一次获取全部交付内容，同时不能把 ZIP 提前放入公开目录或绕过单文件下载权限。
- 影响：`/api/v1/scripts/[id]/files/all` 与单文件下载使用相同授权边界，响应禁止缓存；当前文件体量较小，ZIP 在请求时生成，未来大文件场景再替换为流式归档实现。

## D-014：并发写入与调账重试必须在服务端保护

- 状态：生效中
- 决策：后台编辑和删除剧本必须提供读取时的版本，以 If-Match 传入；事务内先锁定剧本，再检查售出状态和版本。心源调账使用全局唯一 operationId，重复请求只能产生一条流水。
- 原因：页面禁用按钮不能防止并发购买、两个后台编辑覆盖或网络丢失响应后的重复调账。
- 影响：调用方重试调账必须复用编号；相同编号不同用户、操作者、金额或原因被拒绝。前端私有状态与页面表单按用户 ID 和角色隔离。新增迁移 0005，仅增加可空操作编号及唯一索引，历史流水保持原样。

## D-015：统一临时任务目录并执行一次性清理

- 状态：生效中；用户于 2026-09-06 确认
- 决策：临时脚本、测试夹具、截图和运行日志等统一在 var/tmp 的任务独立子目录中生成；任务结束后清理自身一次性产物。需要保留的临时产物须注明用途和清理条件。
- 原因：避免模型开发过程积累散落文件，让 LLM Wiki 保持为长期知识库。
- 影响：Git 和 Docker 排除临时内容；测试使用 finally/trap 自动清理。长期测试在 scripts，最终交付放正式目录。清理不得波及其他任务、用户文件、持久存储、备份、数据库或 sources。

## D-016：采用双画幅交叠的心智品牌标志

- 状态：生效中；用户于 2026-09-07 确认
- 决策：心智统一使用两个交叠影视画幅组成的几何标志，品牌强调色为心智朱红 `#D84A3F`，搭配近黑与暖白。公司级英文名称使用 `XINZHI PICTURES`。
- 原因：双画幅表达剧本、制作与成片之间的连接，中央交叠区域代表故事核心；抽象符号比播放键、机器人或大脑图标更适合建立长期识别。
- 影响：正式资产进入 `public/brand`，网站统一通过 `src/components/xinzhi-brand.tsx` 组合标志与文字；后续页面不得重新绘制另一套标志或随意改变画幅关系、颜色和比例。具体规范见 `docs/BRAND_IDENTITY.md`。

## D-017：门户媒体以网页传输效率为交付标准

- 状态：生效中；用户于 2026-09-07 确认
- 决策：首页 PV 从高质量母版使用 FFmpeg 生成兼容浏览器的 720p H.264 高质量压缩版；加载时先展示封面，达到可平稳起播状态后静音自动播放并淡入。后台上传的剧本封面和首页滚动海报若超过各自上限，由浏览器在本地优先保留高画质压缩为 WebP 后再提交；首页海报提交文件仍不得超过 1 MiB。
- 原因：门户首屏媒体是当前最大的网络成本；在单机首发架构下，控制视频与海报体积可以直接改善起播速度和带宽占用。
- 影响：已符合上限的图片保持原文件，避免无意义的二次压缩；超限图片不先传服务器，前端展示压缩状态和前后大小。服务端仍执行最终体积、格式、像素和权限校验，不能把浏览器处理视为安全边界。本机性能数据只用于改动前后的相对对比，正式上线前必须在目标服务器、生产网络和真实终端重新验收。

## D-018：首次生产部署使用全新业务数据

- 状态：生效中；用户于 2026-09-08 确认
- 决策：首次生产部署不迁移本地开发环境中的用户、订单、积分、剧本、海报或上传文件；生产数据库从全部正式迁移开始，只初始化一个管理员。首次上线入口为 `https://xinsee.cc:8443`；该入口已由 D-021 替代。
- 原因：本地数据全部属于交互与流程测试，不应污染正式订单、权限和内容状态。
- 影响：生产剧本、海报、注册码和会员必须重新通过管理员后台创建；初始化管理员密码仅在部署交接时提供，不写入代码、Wiki 或长期环境变量。Caddy 将页面和全部 API 统一代理到同一个 Next.js 应用容器。

## D-019：新建私有存储卷必须自动初始化权限

- 状态：生效中；目标服务器验收于 2026-09-08 发现并修复
- 决策：生产 Compose 使用一次性 `storage-init` 服务，在应用或自检启动前把私有存储卷设为容器 UID/GID `1000:1000` 和目录权限 `0700`。
- 原因：Docker 新建命名卷默认由 root 拥有，会导致非 root 应用无法上传文件，也会使生产自检失败。
- 影响：应用和生产自检都依赖 `storage-init` 成功完成；部署时不得绕过该服务或通过放宽目录权限解决。

## D-020：首页海报采用稳定物理速度并由后台统一控制

- 状态：生效中；用户于 2026-09-08 确认
- 决策：首页海报长廊保存一个全局像素速度，范围为 15-60 px/s，默认 30 px/s。前台根据当前轨道长度自动换算完整循环时长，不为单张海报分别设置速度。
- 原因：固定一圈时长会随着海报数量和屏幕宽度改变实际移动速度；单张速度也无法用于同一条连续轨道。
- 影响：速度通过后台首页海报管理区修改，写入 `showcase_settings` 并记录审计日志；公开海报 API 同时返回设置，门户刷新后生效。新增迁移 `0006_showcase-reel-speed`。

## D-021：生产规范入口切换到独立 Drama 子域名

- 状态：生效中；用户于 2026-09-11 确认
- 决策：心智门户与剧本库的生产规范入口切换为 `https://drama.xinsee.cc:8443`，DNS A 记录指向当前生产服务器公网地址；应用的 `NEXT_PUBLIC_APP_URL`、身份可信来源、元数据基址和生产验收统一使用该入口。
- 原因：根域名曾解析到另一台旧服务器，导致 8443 端口不可达；独立子域名能够明确区分心智剧本库与其他产品，并直接指向当前生产主机。
- 影响：Caddy 同时为新域名的 443 和 8443 提供 HTTPS，443 重定向到规范的 8443 入口；旧域名规则暂时保留兼容。公网地址发生变化时必须同步更新 DNS，或后续改用稳定隧道/动态 DNS，不能只修改应用容器。

## D-022：AI能力留在外部Skill，服务器只接受受限草稿导入

- 状态：生效中；用户于 2026-09-12 确认
- 决策：剧本库本身不集成模型、AI SDK或提示词。获得管理员灰度授权的用户可使用与本人绑定的Key，通过官方Skill和 `/api/agent/v1` 提交剧本草稿；价格固定为0且不能直接发布。手工上传继续保留。
- 原因：用外部Agent减少资料填写工作，同时避免把模型依赖、供应商费用和不稳定解析逻辑放入正式业务系统。
- 影响：管理员后台统一管理灰度资格、Key、导入记录和草稿审核；Key明文只返回一次且保存在Skill目录之外。Skill每次运行先校验服务器版本，更新须由用户确认并从官方同域HTTPS地址下载后校验。服务器不信任Skill本身，权限、版本、幂等、限流、文件和字段始终由服务端执行。D-004关于“系统不自动解析”的边界保持有效，但授权用户可由外部Agent创建草稿，正式发布仍只能由管理员完成。详细规则见 `docs/agent/API_CONSTITUTION.md`。

## D-023：Agent正式入库采用只读源目录与确定性发布包

- 状态：生效中；用户于 2026-09-13 确认真实项目标准
- 决策：`xinzhi-script-uploader` v1.1.0 只启用“英文正式剧本 + 中英对照正式剧本 + 完整导演阐述 + 精确2:3封面”的 `bilingual-package`。AI负责标题、genre、tags、试读理由和制作执行摘要等语义判断；本地标准库负责词数、集数、模块配对、完整EP试读、封面像素、文件边界、SHA-256、大小、成人风险和幂等编号等确定性校验，并只在项目外复制生成 `心智发布区` 标准包。
- 原因：真实两次草稿测试已证明“完整导演阐述附件 + 500–1000中文字符制作执行摘要”能兼顾交付完整性与页面可读性；同时必须消除按修改时间误选历史文件、失败换幂等编号和用开放数量隐藏风险试读等不确定行为。
- 影响：`parallel-production`只保留协议定义，不默认开放；需要真实样本重新勘察和测试后另行启用。外部Agent上传前必须展示审核摘要并获得用户确认。服务端继续独立强制草稿、版本、限流、正式包模式、genre、摘要长度、试读和封面比例，不能信任Skill未被修改。
