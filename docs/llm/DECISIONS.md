# 心智项目关键决策记录

这里记录已经确认、会长期影响开发的产品和架构决策。后续如果需要改变某项决策，应新增一条“替代”记录并说明原因，不直接抹掉历史。

## D-001：采用 API 优先的模块化单体

- 状态：生效中
- 决策：前端页面与后端 API 放在同一个 Next.js 项目和部署单元中，但前端只能通过 API 访问业务数据。
- 原因：当前规模下维护和部署成本最低，同时保留未来拆分后端、增加 App 或海外站的能力。
- 影响：复杂业务规则进入 `src/modules`，API 路由保持轻薄，组件不能直接访问数据库。

## D-002：门户公开，剧本详情采用白名单

- 状态：生效中
- 决策：门户首页和剧本库卡片公开；导演阐述和试读仅白名单会员可看。
- 原因：兼顾公开获客和核心内容保护。
- 影响：游客 API 只返回卡片所需信息，详情接口必须在服务端检查会话。

## D-003：一人一码注册

- 状态：生效中
- 决策：普通用户只能用管理员生成的一次性注册码注册，一个注册码只能成功使用一次。
- 原因：早期控制用户质量和内容访问范围。
- 影响：完整注册码不写入数据库，只保存带密钥的摘要；使用、撤销必须留状态。

## D-004：系统不自动解析上传剧本

- 状态：生效中
- 决策：管理员上传 Word、TXT 或 Markdown 原文件，同时手工填写公开资料和试读内容；系统暂不使用 AI 或格式解析器生成展示内容。
- 原因：不同剧本格式差异大，自动解析失败会增加后台返工和内容错误。
- 影响：原文件只用于购买后交付，前台展示完全来自管理员填写的数据。

## D-005：一个剧本只成交一次

- 状态：生效中
- 决策：每个剧本只能产生一个已完成购买订单。
- 原因：当前售卖的是独家授权，不是重复销售的数字商品。
- 影响：购买必须锁定剧本并使用数据库事务；成交后其他用户不能查看详情或再次购买，但剧本库首页保留不可点击的已售出卡片。

## D-006：完整文件只能由买家下载

- 状态：生效中
- 决策：完整剧本、中英对照或中文制作稿、导演阐述作为私有文件保存。
- 原因：试读与交付文件的权限不同，不能依赖前端隐藏按钮保护内容。
- 影响：文件不进入 `public`，下载 API 必须核验已完成订单和当前用户身份，响应禁止缓存。

## D-007：心源定价与充值优惠分离

- 状态：生效中
- 决策：固定 `1 元 = 100 心源`；剧本统一按心源扣费，不设置账号折扣；优惠通过充值赠送心源实现，最高等效四折。
- 原因：让剧本价格、用户余额和财务流水保持简单、可审计。
- 影响：充值档位允许不同赠送比例，但账号本身没有折扣字段。

## D-008：支付宝暂时只留接口

- 状态：生效中
- 决策：保留电脑网站支付宝支付的适配器边界和数据库结构，但当前不接入真实支付。
- 原因：先完成内容、会员和独家交易闭环，再决定支付上线时间。
- 影响：`PAYMENT_DRIVER` 必须保持 `disabled`；个人中心显示“暂未开放”。

## D-009：初期使用本地私有存储

- 状态：生效中
- 决策：初期剧本文件使用服务器持久磁盘，不使用 OSS。
- 原因：文件体量和业务量较小，本地存储更轻量。
- 影响：所有文件通过 `StorageProvider` 访问；生产必须挂载持久卷并执行异机备份；未来迁移 OSS 时增加适配器并按 SHA-256 校验迁移。

## D-010：保持心智现有视觉语言

- 状态：生效中
- 决策：门户和剧本库保持深色、克制、影视编辑感；门户强调 PV 和作品，剧本库强调专业阅读与独家授权。
- 原因：符合 AI 漫剧公司的品牌定位，并避免后台模板感。
- 影响：新增页面应复用当前排版、颜色、留白和交互节奏，不引入无关主题系统。

## D-011：采用单机 Docker Compose 作为首发部署

- 状态：生效中
- 决策：首发使用反向代理、单个应用容器、PostgreSQL 和两个持久卷。
- 原因：当前阶段不需要 Kubernetes 或微服务平台，单机结构更易维护和恢复。
- 影响：应用和数据库不直接暴露公网；上线前运行迁移、自检和备份；需要 HTTPS、持久磁盘和异机备份。

## D-012：注册协议同意必须由前后端共同校验并留痕

- 状态：生效中
- 决策：白名单注册必须同时同意用户协议和隐私政策；后端拒绝未同意请求，并在用户记录中保存协议版本与同意时间。
- 原因：前端勾选框只能表达交互，不能作为可靠的注册规则或历史凭证。
- 影响：协议升级时更新 `identity/policies.ts` 中的版本；上线前必须补全真实运营主体、联系方式并进行正式合规审阅，不能把当前通用文本视为法律定稿。

## D-013：完整交付包由受保护下载接口动态生成

- 状态：生效中
- 决策：用户购买成功后，原购买按钮直接变为“下载全部交付物料”；服务端核验买家或管理员身份后，从私有存储读取交付文件并生成 ZIP。
- 原因：用户需要一次获取全部交付内容，同时不能把 ZIP 提前放入公开目录或绕过单文件下载权限。
- 影响：`/api/v1/scripts/[id]/files/all` 与单文件下载使用相同授权边界，响应禁止缓存；当前文件体量较小，ZIP 在请求时生成，未来大文件场景再替换为流式归档实现。
