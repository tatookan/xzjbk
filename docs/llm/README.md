# 心智项目 LLM Wiki 入口

这个目录是给后续模型和开发者使用的轻量项目记忆。它不代替代码和数据库，只保存进入项目时必须知道的结构、状态与已确认决策。

## 每次进入项目先读什么

按以下顺序阅读：

1. 根目录 `AGENTS.md`：不可违反的开发边界和更新规则。
2. `docs/llm/STATE.yaml`：项目当前阶段、已完成能力、限制和下一步。
3. `docs/llm/DECISIONS.md`：已经确认、不能随意推翻的产品与架构决策。
4. `docs/PROJECT_STRUCTURE.md`：需要理解目录或改动范围时阅读。
5. `docs/BRAND_IDENTITY.md`：涉及 Logo、颜色或品牌资产时阅读。
6. `docs/DEPLOYMENT.md`：涉及上线、环境变量、备份或恢复时阅读。
7. `README.md`：开发命令和项目总体说明。

完成上述阅读后，再检查当前代码和 `git status`。代码是实际行为的最终依据；如果文档与代码不一致，先确认差异，不要静默假设某一方正确。

## 三个状态文件各自负责什么

- `STATE.yaml`：现在进行到哪、哪些能力完成、哪些还没做。允许直接更新现状，不保留流水账。
- `DECISIONS.md`：为什么这样设计。采用追加或明确标记“已替代”的方式维护，不直接删除仍有历史价值的决策。
- `PROJECT_STRUCTURE.md`：代码放在哪里、模块如何协作。只有目录或职责发生实质变化才更新。

## 什么时候必须更新 Wiki

发生以下任一变化时，在同一任务中同步更新：

- 新增或删除一个产品模块、顶级目录或主要页面。
- API 版本、数据库、存储、支付、身份或部署架构变化。
- 项目阶段、完成度、生产状态或下一里程碑变化。
- 用户确认了会长期影响开发的新业务规则。
- 原有关键决策被替代或废止。

以下变化不需要更新：

- 单纯修复文案、间距或无业务影响的小问题。
- 代码格式化、依赖锁文件机械更新。
- 没有改变行为的内部重构，除非目录职责也发生变化。

## 更新方法

1. 先修改代码并完成验证。
2. 更新 `STATE.yaml` 中的 `updated_at`、阶段、能力或下一步。
3. 如有新长期决策，在 `DECISIONS.md` 添加一条编号记录。
4. 如目录或职责变化，更新 `PROJECT_STRUCTURE.md`。
5. 检查文档中不要出现密码、注册码、Cookie、密钥或真实用户隐私。

## 状态值约定

项目阶段只使用以下值，避免每个模型发明新叫法：

- `prototype`：只做界面和交互验证。
- `formal_development`：正式数据库和业务开发中。
- `deployment_ready`：代码具备部署条件，尚未正式上线。
- `production`：已经部署并面向真实用户。
- `maintenance`：主要进入维护和小步迭代。

功能状态只使用：`planned`、`in_progress`、`complete`、`placeholder`、`blocked`。

## 临时运行产物

LLM Wiki 保存稳定结论，不存放一次性脚本、截图、接口样本或测试运行日志。所有这类产物统一进入 `var/tmp/` 的任务独立子目录；具体归档、保留和自动清理要求见根目录 `AGENTS.md` 的“临时文件与任务收尾”。任务结束时清理自己的临时子目录，保留用于审阅的产物需说明清理条件。可重复执行的测试保存在 `scripts/`。

## 安全边界

- 不在 Wiki 中记录测试或生产密码。
- 不把完整剧本正文复制进 Wiki。
- 不把 `.env` 内容、数据库连接串或服务器地址写入 Wiki。
- 父级 ChatGPT 项目的 `sources/` 是只读参考资料，不能修改、移动或删除。
